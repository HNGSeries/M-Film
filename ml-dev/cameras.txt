# The cameras Magic Lantern runs on, and where M-Film is on each.
# platform     status    boot-limit  name [| note | note in Thai]   (the notes go in the README's table)
#   status:   working  tried on the camera, works
#             issues   tried on the camera, with a known problem (the note says which)
#             testing  builds; waiting for someone to try it on the camera
#             planned  not started yet, but should be possible
#             nodark   the full build is too big at boot on it, so it's built and released without the
#                      in-camera darkroom (build_fork.sh --no-darkroom): rolls are developed with
#                      Darkrooms on a computer. 650D: a tester's 650D starts with it, the full one doesn't
#             memory   builds, but bigger than the memory Magic Lantern gets at boot on it: the camera
#                      would stop at power on (3 long, 3 short blinks), so it isn't built or released
#                      until that reservation is raised for it, as for the 6D (MEMORY.md)
#             no       not for now: Magic Lantern itself is experimental there (DIGIC 6 and later)
#   :module   after the status (e.g. testing:module): built with the film OS as a module
#             (build_fork.sh --module): ML/modules/filmos.mo, loaded after boot, so autoexec.bin keeps
#             only Magic Lantern and three hooks, ~180 KB less at boot (MEMORY.md)
#   boot-limit: the largest autoexec.bin (bytes at boot) known to start on it, - if not known yet
#             (6D: what the fork reserves for ML at boot, see the 6D edit in fork/apply_fork.py;
#              100D, 70D, 550D, 600D, 1100D: the fixed reservation of Magic Lantern's boot code, MEMORY.md)
